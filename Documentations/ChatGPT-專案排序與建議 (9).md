# 二、最重要修正：加入 Task Contract

你目前的結構是：

```txt
Human SOP
Skill
Agentic Workflow
```

這已經很好，但還缺一個企業級工作流最關鍵的中間層：

```txt
Task Contract
```

建議改成四層：

| 層級 | 定義 | 主要產物 |
|---|---|---|
| **Human SOP** | 給人看的流程說明，包含大量默會知識 | Word、Notion、PPT、Markdown |
| **Skill** | 給 Agent 用的方法包，描述怎麼做 | `SKILL.md`、references、scripts、examples |
| **Task Contract** | 單一任務節點的輸入、輸出、成功條件、失敗條件 | JSON schema、success criteria、blocked stop condition |
| **Agentic Workflow** | 多個 Task、Skill、工具、資料源與人工審核點組成的流程 | pipeline、DAG、runbook、audit log |

最關鍵的差異是：

```txt
Skill 告訴 Agent 怎麼做。
Task Contract 告訴系統怎麼驗證它做完、做對、做壞了該怎麼辦。
```

這一層補上後，你的文件就會從「方法論」升級成「可交付的企業工作流規格」。

# 三、Must / Should / May 要正式工程化

你使用 Must、Should、May 是正確方向，但建議改成全大寫：

```txt
MUST
SHOULD
MAY
```

並補上這句：

> 本文件中的 **MUST、SHOULD、MAY** 採用 RFC 2119 / RFC 8174 的規範語義；只有全大寫形式具備約束力。

RFC 2119 定義了 MUST、SHOULD、MAY 等關鍵詞在規格文件中的要求強度；RFC 8174 進一步澄清，只有這些詞以全大寫出現時才具有該規範含義。([The GitHub Blog](https://github.blog/news-insights/octoverse/octoverse-a-new-developer-joins-github-every-second-as-ai-leads-typescript-to-1/?utm_source=chatgpt.com))

這會讓文件語氣從「顧問建議」提升成「工程規範」。

# 四、「嚴禁硬編碼」要修正

你目前寫：

> 嚴禁將規則硬編碼。

這句太絕對。企業級 AI 工作流中，有些規則應該參數化，有些規則必須寫死成 policy / schema / validator。

建議改成：

> 可變的業務規則 **SHOULD** 參數化；安全邊界、資料型別、權限控制、禁止操作與高風險門檻 **MUST** 以 schema、policy 或 deterministic validation 固化。

範例：

| 規則類型 | 建議做法 |
|---|---|
| 財務審核金額門檻 | 參數化，例如 `finance_review_threshold` |
| 員工 ID 格式 | JSON schema / validator |
| 金額超過 5000 元 | MUST trigger human approval |
| 不得讀取私鑰 | policy guardrail |
| 輸出格式 | schema validation |
| 文字風格偏好 | Rubric / Skill reference |

一句話：

```txt
能安全配置的規則參數化；
不該被突破的邊界程式化。
```

你目前寫：

這適合入門，但企業文件不建議寫成 JSON 是唯一格式。建議改成：

> 節點間資料傳遞 **SHOULD** 優先使用結構化 Artifacts；JSON 是預設格式，但不是唯一格式。長文、表格、檔案、影像與大型中間產物可使用 Markdown、CSV、PDF、file path、object storage URI 或 manifest。

| 場景 | 建議 Artifact |
|---|---|
| 分類結果 | JSON |
| 回覆草稿 | Markdown |
| 財務明細 | CSV |

| 圖片、影片 | file path + metadata |
| 大型中間產物 | object storage URI + manifest |

```json

  "schema_version": "1.0.0",

  "created_at": "2026-05-31T00:00:00Z",
  "payload": {},
  "validation_status": "passed"
}
```

這樣每個節點產物都能被下一步穩定讀取、驗證、追蹤與回放。

# 七、MCP 段落要修正時間與安全邊界

你寫 MCP 是 AI 世界的 USB-C，這個比喻可保留。MCP 官方也將 MCP 定義為讓 LLM applications 與 external data sources / tools 整合的 open protocol。([Model Context Protocol](https://modelcontextprotocol.io/specification/2025-06-18?utm_source=chatgpt.com))

但時間點要修正：Anthropic 是在 **2025 年 12 月 9 日** 宣布將 MCP 捐贈給 Linux Foundation 旗下的 Agentic AI Foundation，不是 2025 年初。AAIF 是 Linux Foundation 旗下 directed fund，由 Anthropic、Block、OpenAI 共同創立，並獲得 Google、Microsoft、AWS、Cloudflare、Bloomberg 等支持。([Anthropic](https://www.anthropic.com/news/donating-the-model-context-protocol-and-establishing-of-the-agentic-ai-foundation?utm_source=chatgpt.com))

更重要的是，MCP 不是自動安全保證。MCP 規格明確提醒，tools 可能代表任意程式碼執行，host 必須取得使用者明確同意，使用者也應理解每個 tool 的作用後再授權。([Model Context Protocol](https://modelcontextprotocol.io/specification/2025-06-18?utm_source=chatgpt.com))

建議新增 MCP 安全檢查表：

```txt
MCP Workflow MUST:
- use least privilege
- log tool calls
- require human approval for high-risk actions
- treat tool output as untrusted data
- restrict filesystem access
- separate read-only tools from write-capable tools
```

# 八、HITL 要寫成 Workflow Gate，不只是人工確認

你現在的 Human-in-the-loop 寫法是對的，但可以更企業級：

> HITL 不只是人工確認，而是 workflow control gate。它決定 run 何時繼續、暫停、拒絕、升級或回滾。

建議補上：

```txt
Workflow MUST pause for human approval when:
- transaction_amount > finance_review_threshold
- admin permission change is requested
- credential access is required
- destructive action is requested
- confidence < confidence_threshold
- policy violation is detected
```

這個方向也和 OpenAI Agents 的 guardrails / human review 概念一致：guardrails 用於自動驗證 input、output 或 tool behavior；human review 可讓敏感行為在執行前暫停等待批准。([AWS 文件](https://docs.aws.amazon.com/prescriptive-guidance/latest/agentic-ai-patterns/introduction.html?utm_source=chatgpt.com))

## Task Contract Template

### Task Name

# 最終結論建議

> 企業級 Agentic Workflow 的本質，不是讓模型變成萬能員工，而是把工作拆成模型能穩定完成、系統能明確驗證、人類能安全接管的任務節點。  
>
> Human SOP 讓人知道怎麼做；Skill 讓 Agent 知道怎麼做；Task Contract 讓系統知道如何驗證；Agentic Workflow 則讓多個任務節點、工具、資料源與審核點形成可運行的自動化生產線。  
>
> 在 AI Agent 原生時代，真正值錢的能力不是「會叫 AI 做事」，而是「能把企業流程拆成 AI 做得穩、測得準、錯得可修、風險可控的系統」。
